# 2026-10-26

## Perch AI 代理可行性评估（只做验证，未进仓库）

结论：**技术可行、合规不可行，放弃**。报告：`docs/PERCHAI-PROXY-FEASIBILITY.md`

关键实测事实（临时目录 `D:/tmp/perch-probe`，**测完已删除**）：
- 无公开 API（`api.perchai.app` 不解析，`/v1/chat/completions` 404）；定价页明示 "direct API access is not included"。
- 凭证来自官方 CLI `perchai-cli@2.4.118`：`perch login github` → `~/.perch/cli-auth-session.json` 明文存 **Supabase ES256 JWT**（1h TTL + refreshToken）。可用 `PERCH_CLI_AUTH_DIR` 改写入目录。
- 内部端点 `POST https://app.perchai.app/api/perch-terminal/model-call`，需 `x-perch-turn-ticket`（先 POST `/api/perch-terminal/turn-ticket`）+ `x-perch-locale` + `user-agent: perchai-cli/<ver>`；请求体 `{request:{messages,tools,...},runId,lane,clientSurface}`，**100 KB**（47,570 字符 system prompt + 44 tools）；SSE 事件 `answer_delta`/`reasoning_delta`/`done(usage)`；有 `x-perch-call-held-*` 增量摘要缓存机制。
- 反滥用闸门 = **官方 system prompt 指纹**：保留即放行任意 user 内容（实测 200 + 正常中文回答），换掉即 403 `perch_surface_required`。tools 可清空。
- 限流：Starter 约 5 次调用后 429 `turn_rate_limited`，恢复 60–90s，`enforced:false`。
- 每次调用固定 ~23,328 token 前缀（22,784 走 cache），模型实际是 `deepseek-ai/DeepSeek-V4.1-Flash`（Roost 路由，Starter 池 pin `wandb-kimi-k2-6`）。
- ToS §6/§7 明令禁止 proxy / 暴露内部端点，且错误响应直接警告"repeated direct-access attempts may result in account suspension"；Starter 默认开启训练数据计划。

抓包方法论（可复用）：改 `dist/perch.mjs` 里 `SWt()` 强制 model-call 指向本地 mitm（`PERCH_CLI_APP_URL` 只覆盖部分调用，`PERCH_MODEL_CALL_PROXY_URL` 会被 `cliServerAppUrl` 分支短路），跑一轮 `perch run` 录原始请求，再逐项改动复放定位闸门。
