## 界面打磨第四轮：明细表圆角 —— 试了一版，被否，已回退

用户追问「明细的圆角没有办法解决吗，之前概览那个表不也解决了吗」。

**差异是真的**：概览 `.model-table-card { overflow: hidden }` 把方角表头夹在卡片圆角里；明细 `.table-wrap` 不能加 overflow（任何 overflow 值都会变成 sticky 表头自己的裁剪框，表头直接被裁没）。

**试的方案**：表头底色改由卡片画 —— `.table-wrap` 铺 `background-image: linear-gradient(var(--surface-head) 0 var(--th-h), transparent var(--th-h))`，`--th-h: 36px`，`th` 去掉圆角只留同色背景。理论静止态无缝、贴顶态通栏方角。

**为什么被否**：背景确实被圆角边界裁得很干净，但那条**方角**色带把卡片内角整个填满，圆角在视觉上消失了 —— 用户原话「这样修不行啦，退回，圆角直接没了」。教训：贴到内弧 ≠ 看起来是圆的；角的可见性靠的是"色块让位给弧线"，而不是"色块被弧线裁"。

**已回退**：`detail.css`（`.table-wrap` 恢复 `background: var(--surface)`、删 `--th-h` 与 `.table-wrap th` 三条、恢复首尾 th 圆角两条）、`theme-jelly.css` / `theme-jelly-dark.css`（`background-color` 改回 `background`）。`grep th-h` = 0，`thh` 回到 35.25，`webui_site` 10 项守门全 PASS。截图 `.probe/shots/fullback-{dark,jelly}-{top,stuck}.png`。

**留下的可用结论**：`background:` 简写会重置 `background-image`（jelly 两档给 `.table-wrap` 设玻璃底时是真的坑）；`corner_radii_come_only_from_the_token_scale` 会咬注释里的 "border-radius" 字面量。若还要修缺口，只剩需要 JS 状态的两条路（贴顶时给 th 收角 / 补反圆角），未做，等指令。



## 界面打磨第五轮：明细表改「卡片外框固定 + 表内滚动」（B 方案）

用户先问「为什么表底的消失位置在表头顶部，按道理不该在表头下沿消失吗」，再补一句「把整个表放容器里是正确的，不然窄屏内容会出框」，选定 B。

**量出来的根因**：整页滚动时，卡片顶边被 `.content` 裁掉的位置（y=51）与表头 sticky 钉住的位置（y=51）是同一条线，卡片顶边只有约 1px 的「被表头吞掉」的行程 → 视觉上就是表头上沿凭空截断。被表头吞掉的行数据其实一直在表头**下沿**（86.3）消失，所以问题不在 `top` 值，在于卡片没有自己的固定外框。

**改动**
- `index.html`：`<table>` 外层加 `.table-scroll`，`.empty` 移进去；`.pager` 留作卡片的固定底条。
- `detail.css`：`.table-wrap` 改成 flex 列 + `overflow:hidden` + `min-height:260px`；`.table-scroll` 是唯一滚动容器（`overflow:auto`、`min-height:0`、`overscroll-behavior:contain`）；`#view-attempts.active` 立成定高 flex 列；`.pager { flex:none }`；删掉 `th` 的两条圆角规则。
- `content.css`：`.content-inner:has(#view-attempts.active) { height:100% }` —— 给 `height:100%` 提供确定父高。

**验证**（`.probe/b-check.js` / `b-zoom.js` / `views-check.js`）
- 1440 / 900：`pageScroll=0`（页面不再滚）、卡片外框零位移、`thPinnedToCard=true`、表宽不越卡片、四主题同构。
- 375：`tableOverflowsCard=true` 但被卡片裁住（横向滚在 `.table-scroll` 内，`innerScroll.x=439`），页面滚 410px 才能到卡片——迷你卡 + 筛选栏本身就超一屏（既有问题）。
- 概览 / 日志视图不受 `:has` 规则影响（`innerHeight` 仍是内容高，`logpane` 仍 640）。
- 抽屉 `position:fixed` 440×900 未被裁。
- 守门测试 10 项全 PASS；`cargo test -p ccproxy` 300 + 若干集成套件全绿，0 失败。

**坑**
- 卡片 `flex:0 1 auto` + `min-height:0` 在 375 会被压成 2px，必须给 `min-height:260px` 当前提；`.table-scroll` 反而要 `min-height:0`，否则分页条被挤出卡片。
- 百分比高度链（`.content-inner` → `#view-attempts` → 卡片）没有 `:has` 会因循环依赖退化成 auto，页面又变整页滚。
- `b-zoom.js` 里行的 `getBoundingClientRect` 对被裁掉的行仍返回坐标，别拿它判断"是否可见"。

## 界面打磨第六轮：卡片按内容长、封顶一屏；贴顶后才内滚（用户："卡片太短了"）

第五轮的 B 方案把卡片交给 flex 分剩余空间（`flex:0 1 auto` + 定高父级），结果卡片只有 chrome 剩下的那一小块，用户报「卡片太短了啦，能不能自己实现表头顶到上面才滚表内的内容，然后表本身比高度稍矮」。

**改动**
- `detail.css`：`#view-attempts.active` 去掉 `height:100%`（不再定高）；`.table-wrap` 改 `flex:0 0 auto` + `max-height: var(--table-max-h, calc(100dvh - 120px))`，删掉 `min-height:260px`；`.table-scroll` 加 `scrollbar-gutter: stable`、`overscroll-behavior` 回默认 auto；新增 `.table-wrap:not(.is-stuck) .table-scroll { overflow: hidden }`。
- `content.css`：删掉 `.content-inner:has(#view-attempts.active) { height: 100% }`。
- `attempts.js`：新增 `fitTableCard()`（写 `--table-max-h = content.clientHeight − paddingBottom`）、`syncTableGrip()`（贴顶或页面到底 → `is-stuck`）、`queueTableGrip()`（rAF 节流）。
- `app.js`：初始化时算一次 + 内容区 scroll 监听 + resize + ResizeObserver(.content)。
- `router.js`：切视图后重算（隐藏视图 rect 全 0，量不到）。

**关键推导**：页面滚到底时卡片顶 y = 视口底 − 卡片高 − padBottom。要让这一项等于内容区顶，卡片高必须 = contentH − padBottom（**只减底 padding**）。之前上下都减会多让出 padTop，卡片顶永远差 20px，`is-stuck` 判不出来 → 表内永远滚不了。

**实测**（新增 `.probe/grip-check.js`，含 CDP `Input.dispatchMouseEvent` 滚轮模拟）
- 1440：可滚 198px，滚轮在表格上 → 页面滚 120、表内 0；滚到底卡片顶 −0.1px、`stuck=true`、`overflow:auto`；贴顶后滚表内 200px、卡片与表头位移 0；回滚向上页面归 0、`stuck` 解除。
- 900 / 375 同构（375 卡片 616px，比第五轮 260px 高得多）。
- hidden↔auto 两态 `scW`/`tableW` 恒为 1130（`scrollbar-gutter` 生效，无宽度跳动）。
- 四主题结构与配色一致；`cargo test -p ccproxy` 300 + 各集成套件全绿，webui_site 10 项守门全 PASS。

**探针坑**：窄屏初始时卡片可能整块在视口外，滚轮坐标必须 clamp 进视口，否则 `Input.dispatchMouseEvent` 静默无效（第一次测出「页面滚了 0px」就是这个假象）。

## 补充：交接真空（用户「中间有很大一段滚动无效」）

**诊断**（`.probe/handoff.js`，CDP 逐格 `mouseWheel` 60px）：页面可滚 198px，前 3 格纯页面滚动；第 4 格页面只剩 19px，浏览器只滚 19、余下 41px 丢弃，第 5 格才进表内——旧版交接处必然丢一次滚轮。更严重的一条：指针落在 `.pager`（卡片底部 48px 高的一整条）或卡片边框内空白上时，那里不在 `.table-scroll` 内，滚轮压根到不了表格，**完全滚不动**。用户感知到的「很大一段」主要来自第二种。

**修法**：`relayTableWheel()` 挂在整个 `.table-wrap` 上（`passive:false`）。
- 判定改成「页面剩余 `pageRoom < px`」而不是「页面已到底」——后者命中时已经丢了一半。命中后 `preventDefault()`，`content.scrollTop += pageRoom` 把页面滚完，剩下的 `px - pageRoom` 直接 `sc.scrollTop +=`，一次滚轮跨过交接点。
- 不命中的情况完全不动：页面整口吃得下 → 原生；`is-stuck` 且指针在滚动区里 → 原生（保住触控板惯性）；向上滚 → 原生链式本来就连续（实测内滚归零后下一格页面就动）。
- `px` 按 `deltaMode` 换算（行 → ×16，页 → ×clientHeight）。

**实测**：1440 第 4 格 Δpage=18 + Δinner=42 = 60；375 第 14 格 2+58=60；指针停在分页条上同样连续。视口高 600/700/800/900/1080/1200 六档贴顶误差恒 −0.1px。守门 10 项 + `cargo test -p ccproxy --lib` 300 全绿，三视图无回归。

## 界面打磨第六轮补充二：交接按「手势」接管（用户「滚到顶/回滚时要动一下鼠标才接替」）

上一版 `relayTableWheel` 只接力**一次**，然后把控制权交回原生。用户实测两个方向都会卡。

**根因（三层）**
1. 页面到底那一次滚轮，余量被浏览器丢掉（上一轮已修）。
2. **Chromium 的 scroll latching**：一整个手势（连续滚轮，间隔 <~200ms）锁在最初命中的滚动容器上。手势中途容器换人（`.content` → `.table-scroll`，兄弟关系不在祖链上），后续滚轮仍作用于已到底的 `.content` → 无效，必须等手势断掉（停手/移动指针重新命中测试）才换过来。**这就是「要动一下鼠标」。** CDP 探针每档 sleep 160–400ms，手势早就断了，所以之前测不出来。
3. 向上滚时指针落在 `.pager` / 边框空白（不在 `.table-scroll` 内）→ 滚轮只滚页面，得把鼠标挪到表格上。

**改法**（`attempts.js`）
- `lastWheelAt` + `WHEEL_GESTURE_MS = 300`：`handover = now - lastWheelAt < 300`，在 early return 之前就更新时间戳，所以「页面整口吃得下」的那些原生档也算在手势里。
- 向下：页面剩余 < px → preventDefault 自行分配；页面已到底时**只有 `!handover` 且指针在 `.table-scroll` 内**才交回原生（先 `syncTableGrip()` 确保表格是 overflow:auto，否则原生命中它也不可滚），同手势内一律自己接。
- 向上：`sc.scrollTop > 0` 无条件接管（指针在分页条上也照样滚表格）；内滚到顶 + 页面到底 + 同手势 → 余量给页面；其余交原生。
- 手动接管时 `content.scrollTop`/`sc.scrollTop` 直接赋值（瞬跳），但只在跨越交接的那一小段手势里发生，手势一断即恢复原生平滑。

**实测**（新增 `.probe/handoff2.js`，30ms 间隔连发模拟同一手势，逐格 60px）
- 1440 向下：第 4 格 Δpage=18 + Δinner=42 = 60，第 5 格起每格 60，22 格合计 1320/1320、**空档 0**。
- 1440 向上：内滚 10 格各 −60，第 11 格页面即 −60（交接零真空），到页顶后自然停止。
- 375 向下：第 14 格 2+58=60，空档 0；375 向上空档 0。
- 指针停在**分页条**上：双向都连续（旧版向上完全滚不动）。
- 慢速 400ms（手势断开、走原生路径）同样每格 60，说明交回原生的分支没有退化。
- `grip-check.js` 贴顶 gap 仍 −0.1px；`views-check.js` 三视图无回归；`cargo test -p ccproxy` 全绿，webui_site 10 项守门全 PASS。

**方法论教训**：测滚动手感时，档间距必须小于 browser gesture 阈值（30ms），否则测出来的是「无 latching 的理想世界」，与真实鼠标体验不符。

## 界面打磨第六轮补充三：滚动驱动完全自管（用户「偶尔瞬移」「没滚到顶也滚页面」）

按手势接管的版本仍有两条毛病，原因是「原生和手推混用」这个前提没去掉。

**两个现象与成因**
1. **偶尔瞬移**：同一手势里有的档走原生（带 ~100ms 插值）、有的档被我们直接赋值（瞬跳），并且原生动画未收敛时被手推打断 → 观感上就是「时不时跳一段」。
2. **没滚到顶也滚页面**：接力监听挂在 `.table-wrap` 上，而卡片下方那几十像素的留白虽然看起来像卡片、DOM 上却在 `.content` 里 → 滚轮落在那儿完全不进 relay，走了原生，于是只滚页面。加上 latch 在旧容器上时同样会掉回页面滚动。

**改法**：明细视图内的纵向 wheel 全部接管，两段滚动合成一条虚拟轴（`0 … pageMax + innerMax`），`rAF` 缓动推进。单一滚动来源既不会瞬移，虚拟轴单调又保证「表格没回到顶不会滚页面」。监听改挂 `.content`，抽屉（`.drawer`）与其它视图排除。
- `driveWrite` 顺序：content → syncTableGrip → sc；反向写会被 `overflow:hidden` 裁掉。
- `page < pageMax && sc.scrollTop > 0` 时把表格归零，避免页面离开底部后表格停在中间、下次贴顶从中间行开始。
- 参数：34%/帧、单帧封顶 190px、收敛 0.5px。

**实测**：见 `.probe/handoff2.js`（逐档 60px，双向、1440/375）、`.probe/mixed.js`（抖动间隔 40/180/420ms、分页条与卡片下方空白两种落点、抽屉）、`.probe/smooth.js`（一档 120px 的逐帧曲线：多帧推进，单帧最多 80% 且是采样起点误差）、`.probe/viewswheel.js`（日志 `.logpane` 仍原生 0→480，`.content` 不动）。全部空档 0、超量 0、按错容器 0。守门 10 项 + `cargo test -p ccproxy` 全绿。

**方法论坑**：缓动会持续几帧，探针发完事件立刻读数会读到中间值 → 误判「丢量」。每档后至少等 200ms 再采样。

## 界面打磨第七轮：整体回退到原生滚动（用户「逻辑太复杂，恢复原生，接受圆角突出」）

用户否掉上一轮的滚轮驱动方案，理由是「一大堆时序和前端竞态」。原话：「恢复原生，这版先接受圆角突出，写入备忘录」。

**回退范围**（全部删除，不留开关、不留兜底分支）
- `index.html`：去掉 `.table-scroll` 包裹，`.empty` 与 `.pager` 回到 `.table-wrap` 里。
- `detail.css`：`.table-wrap` 回到「描边 + 圆角 + background」，删掉 flex 列 / `max-height: var(--table-max-h)` / `overflow:hidden`；删掉 `.table-scroll` 与 `.table-wrap:not(.is-stuck) .table-scroll`；`#view-attempts.active` 的 flex 列整块删除；`thead tr:first-child th:*` 两条圆角删除（`collapse` 下本就不生效）；`.pager` 去掉 `flex:none`。
- `attempts.js`：删掉 `fitTableCard` / `syncTableGrip` / `queueTableGrip` / `driveLimits` / `driveRead` / `driveWrite` / `driveStep` / `driveWheel` / `tableWrapEl` / `wheelDrive` 与 renderAttempts 尾部的 `syncTableGrip()`。
- `app.js`：删掉 content 的 scroll 监听、`wheel` 监听、ResizeObserver、resize 重算。
- `router.js`：删掉切视图后的 `fitTableCard`/`syncTableGrip`。
- `content.css`：删掉解释 `--table-max-h` 的注释。

**保留**：`th { background: var(--surface-head) }`（实色表头，有守门测试）与 `tbody tr:first-child td { border-top: none }`（避免与表头 inset 阴影叠成粗线）。

**已知且接受的代价**（已写入 MEMORY.md，防止下次又去"修"）
1. 表头方角压在卡片圆角外侧一点。裁它必须给卡片 overflow，而 overflow 会成为 sticky 表头的裁剪框——贴顶时表头本来就要画到卡片盒外，会被一并裁掉。互斥，选原生。
2. 窄屏 780px 的表比卡片宽、横向穿出右边框，靠 `.content` 整页横滚够到（375 实测 `hMax=422`）。
3. 滚动时表头盖住卡片上边框（native sticky 正常表现）。

**验收**（新增 `.probe/native-check.js`，四主题 × 1440/900/375）
- `hasTableScroll=false`、`wrapOverflow=visible`、`wrapRadius=12px`。
- 真实滚轮 3 档 × 200px：`pageScroll=600`、`innerScrolls=[]`（没有任何内层滚动区在滚）。
- 1440/900 贴顶后 `thY == contentTop`（51/51、110/110）；375 需滚约 780px 才贴顶，属正常。
- 表头底色取到四档各自的值：dark `rgb(28,33,48)`、jelly `rgb(255,255,255)`、jelly-dark `rgb(72,61,101)`。
- `webui_site` 10 项守门全 PASS；`cargo test -p ccproxy` 全绿。

## 界面打磨第八轮：圆角回来（用户「回退不对，怎么还有个尖角。我说退回圆角，接受出框」）

第七轮整条退回原生时，我把表头的圆角一并删了（当时写成「表头方角，压在卡片圆角外侧」），用户看到尖角立刻打回：他要的是**圆角回来 + 接受窄屏出框**。

**改法（两步）**
- `.table-wrap > table { border-collapse: separate; border-spacing: 0 }`（`collapse` 下 Chrome 不裁单元格自己的圆角）。
- `.table-wrap thead tr:first-child th:first-child/:last-child { border-top-*-radius: calc(var(--radius-card) - 1px) }`，比卡片小 1px 是因为卡片有 1px 描边。
- 两条都限定 `.table-wrap` 作用域，防止动到概览那张靠 `overflow:hidden` 收边的模型表。
- 仍然**没有**任何 overflow、没有内层滚动、没有 JS —— 滚动还是原生整页。

**验收**（新增 `.probe/corner-now.js`：输出 computed + 两角 3 倍放大 + 整页，卡片在首屏外时先滚进视野）
- 四主题 × 1440/900/375：`radiusL/R=11px`、`collapse=separate`、`wrapOverflow=visible`、`wrapRadius=12px`。
- 两角放大图确认静止态弧线干净、与卡片描边贴合（dark / light / jelly / jelly-dark 都看过）。
- 贴顶态 `thY == contentTop`（1440 51/51、375 148/148）；两上角的小缺口在深色档几乎看不出（表头 #1C2130 与卡片底只差一点点）。
- 概览页截图确认模型表未被波及。
- `webui_site` 10 项守门全 PASS（`corner_radii_come_only_from_the_token_scale` 未反咬，注释里别写 `border-radius` 字面量）。

**用户明确接受的代价**（写进 MEMORY，别再动）：表头贴顶时两上角有小缺口；窄屏 780px 的表横向穿出卡片右边框，靠整页横滚够到。

## 界面打磨第九轮：抽屉里的表出框（用户截图「内容不多但出框」）

**两个全局规则的锅**，都在 `detail.css`，本来只服务 12 列明细大表：
1. `table { min-width: 780px }` → 抽屉里那张两列小表也被命中，440px 的抽屉塞 780px 的表。实测 `tableW=780 / bodyScrollW=812 / hScroll=373`。
2. `th, td { white-space: nowrap; overflow: hidden; text-overflow: ellipsis }` → 值单元格的 min-content 就是整串模型名，auto 布局下 40% 的列宽被撑开。

**改法**（只动 `.drawer-table`，不碰全局，避免影响明细大表和模型表）
- `.drawer-table { min-width: 0; table-layout: fixed }`
- `.drawer-table td { white-space: normal; overflow: visible; text-overflow: clip; overflow-wrap: anywhere }`（用 anywhere 而不是 break-word：后者不参与 min-content 计算）
- `.drawer-tokens b { overflow-wrap: anywhere }`

**验证**（新增 `.probe/drawer-check.js`）
- 1440：`tableW` 780→407、`hScroll` 373→0、`maxCellRight` 1797→1424（抽屉右边 1440）。
- 375：`tableW=312`（body 344）、`hScroll=0`；jelly / jelly-dark / light / 900 同构。
- 抽屉内滚到底：`hScroll=0`，费用表与尝试链都没越界。
- `webui_site` 10 项守门全 PASS。
