## 10:30 v0.7.6：代理运行时降级 + JPEG 重编码（已提交，待发版）

### 背景
- 生产事故：Clash Verge 出口节点失效后，ccproxy 的 `proxy:"default"` 只在启动时探测一次，
  已通过的代理被一路沿用 → 全部请求死在 `tls connection init failed: unexpected end of file`
  （ureq→rustls 在 TLS 握手前收到 EOF；本地 mihomo 接受 CONNECT 后掐断隧道，41ms 即失败）。
- 用户切全直连后恢复，本次把该漏洞补成自动兜底。

### 代理降级（proxy.rs / upstream.rs / server.rs）
- `Egress` 新增 `auto_fallback`（仅 default 为 true）、`degraded: AtomicBool`、
  `consecutive_faults: AtomicU32`；`bypasses()` 在 degraded 时对全部 host 返回 true。
- 归因：`TransportFault::is_proxy_attributable()` = `ProxyFailed | Reset`。HeaderTimeout /
  Dns / ConnectTimeout 均视为"隧道已通"的证据，会清零连续计数。
- 阈值 `PROXY_FAULT_LIMIT = 3`（一次请求内部 3 次 attempt 全失败即触发）；`degraded.swap`
  保证 WARN 只打一次。显式代理 URL 的 `auto_fallback=false`，保持"指令"语义不静默绕过。
- `send_to_cc` 三个分支接线：Streaming/`Attempt::Failed`(HTTP 错误，fault=None) 上报 None；
  `Err(transport)` 上报 `err.fault`。`/health` 加 `egress:{proxied,degraded}`。
- 端到端验证（隔离实例 + 自写 flaky CONNECT 代理，flag 文件控制转发/掐断）：
  第 3 次失败打出降级 WARN → 下一请求 HTTP 200 走直连 → `/health` = `degraded:true`。

### 图片压缩（image_compress.rs）
- MIME 白名单扩到 `image/png|jpeg|jpg`；`decode_to_rgb` 分派 png/jpeg
  （`jpeg-decoder 0.3`，default-features=false 去掉 rayon）；CMYK/L16 透传。
- 门槛语义改为**解码后原始字节**，`DEFAULT_MIN_BYTES` 300_000 → 500*1024；base64 按 4/3 预筛。
- EXIF Orientation(0x0112) 解析（APP1 段 + TIFF IFD0 双端序）；异常方向一律透传。
- 测试：image_compress 16 项 + 全 workspace 250/55 全绿；clippy 干净、fmt 通过。
